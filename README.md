## 数据来源
BelleGroup/train_2M_CN（HuggingFace），约 1.80GB。
下载后放到 ../input/train_2M_CN.json

## 环境要求
Python 3.13 / JDK 17 / PySpark 4.2.0 / Windows 需 winutils + hadoop.dll

## 运行方式
python cat.py
输出到 ./output/sft_dataset/（JSONL 格式，每行一条）

## 项目内容
1. 项目背景（为什么做这个 / 数据从哪来）
- 为了提高自身spark水平，数据存在重复冗余和模板化现象，直接训练效果不佳
- 为之后的RAG项目做预热
- 数据来自于BelleGroup的（https://huggingface.co/datasets/BelleGroup/train_2M_CN） 生产中文对话内容项目
2. 数据画像（你查到的所有数字）

| 项            | 条数 | 占比 |
|:-------------| ---: | ---: |
| 总数           | 2,000,000 | 100% |
| 空输出          | 12 | ~0% |
| 过短（<10）      | 33,848 | 1.69% |
| 整行完全重复       | 29,844 | 1.49% |
| 重复 output 涉及 | 137,656 | 6.88% |
| 超长（>1500）    | 12,805 | 0.64% |
| 超长（>2000）    | 5,148 | 0.26% |
| 前 20 前缀      | ~349,000 | 17.5% |

3. 目标产出（文件格式、字段、预计规模）
- JSONL格式的高质量SFT训练子集
- 预计得到 180万 ~ 190万 条数据
- 实际产出：1,863,135 条（原始 200 万，删除 136,865 条，占 6.84%）

4. 处理策略（核心，逐条写）

| 规则               | 依据 |           影响 |
|:-----------------| :--- |-------------:|
| 删除 output 为空     | 无内容，无法训练 |         12 条 |
| 按 output 去重，保留一条 | 完全重复不增加信息 |   103,017  条 |
| 过滤 output 长度 <10 | 过短无信息量 |     33,848 条 |

原始数据中涉及重复的样本共 137,656 条，单独去重应删 122,074 条。因长度过滤先行，其中 19,057 条重复样本已随过短样本一并删除，故去重实际影响 103,017 条。
- 处理顺序：先过滤长度（同时清除空值），再按 output 去重。顺序影响最终条数

5. 验收标准（怎么算做完了）
- 最终条数在 180万 ~ 190万 之间
- 无空值、无长度 < 10、无完全重复
- 文件能被 spark.read.json() 正常读取
- 随机抽 100 条人工检查，无异常


6. 未解决的问题
- 按 output 去重时保留哪一条 —— 两条 output 相同但 instruction 不同，留哪条？
- 长度阈值 10 没验证过 —— 没抽样看过这 33,848 条是不是真都没用
- 图片链接类样本是否应过滤，未决定
- 分类方法为关键词匹配，精度有限（"其他"占 29.1%），未做人工校验


7. 已知限制
- 数据中存在少量含 Markdown 图片链接的样本（3,502 条，0.19%）与含 URL 的样本（7,499 条，0.40%），未做处理。这类样本对文本训练价值有限。
- 原计划对高频模板降采样。实测分类后，六类分布为 5.2%~29.1%，未出现单一类别占绝对多数；且关键词分类精度不足以支撑"该砍哪一类"的决策，故放弃降采样，保留原始分布。
