# 中文指令数据集质量看板 · 数据字典与指标口径

## 一、数据来源
BelleGroup/train_2M_CN（HuggingFace），原始约 200 万条、1.8GB。
经边界清洗（output 长度 ≥ 10）与按 output 去重后，产出 1,863,135 条。

## 二、字段说明
| 字段 | 类型 | 含义 | 口径                                                   |
|---|---|---|------------------------------------------------------|
| cluster | 维度 | 指令类别 | 关键词规则打标，七类；「其他」占 30.8%，精度有限，**未做人工校验** || instruction | 文本 | 指令 | 原始字段，未做改写                                            |
| output | 文本 | 回答 | 原始字段，未做改写                                            |
| output_len | 度量 | 回答字数 | = LENGTH(output)，按字符数计（中文一个字算 1）                     |
| length_bucket | 维度 | 长度分桶 | <50 短 / 50-200 中短 / 200-500 中 / 500-2000 长 / ≥2000 超长 |
| has_code | 度量 | 是否含代码块 | output 中是否出现 ```；1 是，0 否                             |
| has_url | 度量 | 是否含链接 | output 中是否出现 http                                    |
| has_img | 度量 | 是否含图片标记 | output 中是否出现 ![                                      |

## 三、指标口径
- **总条数**：清洗去重后的最终条数 = 1,863,135
- **去重减少条数**：1,966,152（清边界后）− 1,863,135（去重后）= 103,017
- **整体过滤率**：(2,000,000 − 1,863,135) / 2,000,000 = 6.8%
- **类别占比**：该类条数 ÷ 总条数
- **重复 output 组数**：15,582

## 四、已知限制与口径陷阱
1. 「重复 output 15,582」是**组数不是条数**，不可与条数直接相加；
   该批重复实际涉及约 12.2 万条记录。
2. `cluster` 用关键词匹配，精度有限，「其他」类占 30.8%，未做人工校验——
   因此**不建议基于该字段做任何"砍掉某一类"的决策**。
3. 长度按**字符数**统计，不是 token 数；如需 token 口径需另接 tokenizer。
4. 数据仍存在模板化现象，但未做降采样，**保留原始分布**。
5. 「其他」占比偏高（30.8%）部分来自关键词规则覆盖不足：
  高频句式「回答以下问题」出现 46,412 次，却未被问答类关键词命中。
6. Spark 直接统计与 MySQL 落库后统计的类别分布存在 42 条（0.002%）差异，
  总数一致。推测与 JDBC 写入过程中文本正则匹配行为有关，未进一步定位。
7. 长度分布（见看板「长度分布」卡片）：中档 200-500 字占 32.1%（598,026 条）为最大桶，
   超长（≥2000）仅 0.3%。P50 = 269，P90 = 700，P95 = 818，P99 = 13,535。
8. 分类一致性抽查：类别占比实测与 `cluster` 字段定义一致；
   `has_code` 命中 246,424 条（13.2%），说明该数据集含可观代码样本，对 SFT 有实际价值。

## 五、结论（这个看板回答了什么）
1. **假设验证结果**
   - 「长度截断」：**否证**。P95 = 818，P99 = 13,535 之间存在断崖，
     且 ≥2000 字的仅 5,151 条（0.3%）；无阈值截断痕迹
   - 「图片占比高」：**否证**。含图片标记 3,502 条（0.19%），含链接 7,499 条（0.40%）
   - 「模板化严重」：**成立，且高于原判断**。instruction 前 6 字 Top10 合计 245,107 条
     （13.2%），单个句式「回答以下问题」出现 46,412 次
2. **类别分布不是问题**：七类占比 5.2% ~ 30.8%，不存在单一类别主导 →
   原定的降采样方案失去依据，已放弃
3. **这份数据的问题不是"脏"，是"单调"**：清洗价值不在于去冗余（6.8%），
   而在于是否要为模板化做去重或改写——这是"该不该做"的决策，不是"能不能做"的技术问题
